## Ground rules

1. Write everything yourself from public literature. Do not copy text from other skill packs, books or standards.
2. No employer, brand, plant, customer, product or person names in `skills/`, `agents/` or `evals/`. The linter blocks a public list of brand terms, and maintainers keep a private list too.
3. Every number needs a source in `references/`, or a label: "rule of thumb" or "set by local policy".
4. Standards are pointers: a clause number plus your own summary. Never paste standard text.

## Add a skill

1. Pick the stage prefix: `lead-`, `measure-`, `improve-`, `plan-`, `solve-` or `audit-`.
2. Write the three eval cases first: `normal`, `missing-data` and `trap`.
3. Write `SKILL.md` with these sections, in this order: Conventions, Inputs, Procedure, Validation, Output, Pitfalls (at most 7), Hand-offs.
4. Put definitions, formulas and worked examples in `references/`, and fill-in templates in `assets/`.

`SKILL.md` stays at or under 500 lines and about 5,000 tokens. The description is at most 1,024 characters and contains "Use when".

## Checks

```
python3 scripts/lint.py
python3 -m unittest discover -s tests
claude plugin validate . --strict
```

The `skill-reviewer` agent then reviews the skill against the writing rules.

## This site

The site is built with Astro Starlight from `docs-site/`:

```
cd docs-site
npm ci
npm run dev
```

The logo, favicon and the hand-off diagram are generated by the tools in `design/brand/tools/`. Change the tools and run them again; do not edit the generated copies.
